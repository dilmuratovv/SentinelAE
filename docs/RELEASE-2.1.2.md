SentinelAE 2.1.2: refreshed chunks are filtered for every player, not only the first.

- **Chunk packets shared between players are no longer changed in place.** `World#refreshChunk` (WorldEdit, region, hologram and many other plugins call it) builds ONE chunk packet and Paper sends that same object to every player watching the chunk. AE used to write its rewrite into that shared packet: the first player's filter hid the storage blocks and recorded them, and every later player on the same network thread got bytes that were already rewritten, so their filter found nothing to record and **never revealed those chests to them** — not when in plain sight, not when the wall between was removed — until something else resent the chunk. Players on different network threads raced on the same bytes while they were being encoded. Now the rewritten bytes and the trimmed block-entity list go into a copy of the packet for that player only (classes on 1.21.x, the record on 26.x); the shared packet is never touched. If a future server shape cannot be copied, AE falls back to the old in-place rewrite and says so once in the log.
- `ChunkFilter.hide` returns the rewritten bytes instead of overwriting its input.

Tests: 30 unit tests (new: a shared buffer gives every player the whole result and stays unchanged; packet copies of the 1.21.x class shape and the 26.x record shape keep every other field and leave the original alone). New live test `tools/refresh_probe.py` with the test plugin `tools/refresh-probe`: two players on one network thread (`spigot.yml netty-threads: 1`, as on a busy server with more players than threads), three refresh rounds. AE 2.1.1 fails it (the second player never sees the chest in sight again, nor the hidden chest after the wall goes: 11/15); 2.1.2 passes 15/15 on Paper 26.3, 1.21.11 and 1.21.1, also together with SentinelAX-ray 2.2.2 (storage on 1.21.11, ore on 26.3). AE probe 19/19 unchanged.
